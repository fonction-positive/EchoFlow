# EchoFlow

Mac 麦克风 → 本地 Whisper 英语识别 → DeepSeek 上下文校对翻译 → 中英对照悬浮字幕。

这是 Apple Silicon、macOS 15+ 的自用原生应用。Swift + whisper.cpp，不使用 Python，不需要虚拟环境，不安装全局 Python 依赖，也不需要付费开发者证书。构建使用本地 ad-hoc 签名。

## 使用

1. 双击 `build/EchoFlow.app`。
2. 展开「DeepSeek API 密钥」，输入自己的密钥并保存。密钥存入 macOS 钥匙串，不写入项目和录音文件。系统询问钥匙串访问时，核对应用名称后由你授权。
3. 点击「开始录音」，首次使用允许麦克风访问，尚未设置默认目录时会提示选择，之后直接保存到默认目录。
4. 等待模型加载完成、界面显示「录音中」后开始说英语。「悬浮字幕」可重新打开字幕窗；拖动背景移动、拖动边缘调整大小。
5. 点击「停止录音」后可给本次录音命名，或跳过使用日期时间；后台识别和校对会继续。名称保存在记录信息中，不改动底层文件夹。
6. 「默认保存目录」可更改以后录音的保存位置；已有记录不会搬迁。
7. 点击「历史记录」浏览默认目录下的本应用记录，选择后在 App 内查看最新中英字幕；「在 Finder 中打开」可查看 WAV/TXT/SRT 文件。旧版没有名称信息的记录显示文件夹名。

字幕窗以中英列表显示全部会话历史，默认自动滚到底部。手动滚动会暂停跟随，点击「回到最新字幕」恢复；字幕会随上下文更新，不是定稿。

字幕窗可跨桌面显示，并配置为支持全屏应用的辅助窗口；具体全屏行为仍需在目标应用里验证。关闭主窗口不会停止正在进行的录音，点击 Dock 图标可重新打开。退出应用时，如果仍在录音或处理，会先提示。

首次构建已下载并内置约 1.5 GiB 的 `large-v3-turbo` 模型。以后打开应用不需要再次下载。音频只在本机处理，当前英文和最近的中英字幕上下文通过 HTTPS 发送到 DeepSeek；翻译需要网络和 API 余额。当前模型是 `deepseek-flash`，显式关闭思考模式并开启流式输出。

## 保存内容

每次录音生成 `LiveTranslate_日期_时间_标识/`：

| 文件 | 内容 |
| --- | --- |
| `audio.wav` | 一场录音一个 WAV，16 位 PCM，保留麦克风原始采样率和声道数 |
| `english-raw.txt` | 最新本地识别原文，不被 AI 校对覆盖 |
| `english.txt` | 带会话相对时间的 AI 校对后英文 |
| `chinese.txt` | 带会话相对时间的中文译文，失败和等待状态明确标记 |
| `bilingual.srt` | 中英对照字幕，按音频时间排序 |
| `session.json` | 录音标题、开始/结束时间和时长；旧版记录没有此文件也可浏览 |
| `events.jsonl` | 每次识别与 AI 修订的记录，包含片段 ID、版本号、原始英文、校对英文、中文、不确定标记与初版中文延迟；同一个 ID 的最后一条为最新状态 |

识别后立即保存英文，同一片段的草稿与最终识别使用同一 ID；AI 校对后更新最新 TXT/SRT，并将每个修订追加到 JSONL。原始 WAV 不改变。网络失败不会中止录音。当前版本不自动重试失败翻译，原始录音和英文仍可用于后续处理。记录不会自动清理，注意磁盘空间：48 kHz 单声道 16 位 WAV 每小时约 346 MB，双声道约 691 MB。

## 延迟与长时间运行

- 本地使用 large-v3-turbo，Metal 加速、beam size 5。语音窗口累积最长 28 秒，每 3 秒产生一个可修订草稿；至少保留 12 秒上下文后可在 1.2 秒安静处结束，停止录音会提交不足一个窗口的尾段。
- 更完整的音频会重新识别并替换同一条字幕；Whisper 继续使用前两段已完成的原始识别作为提示词，发现长串循环重复时排除该异常段，不将其压缩后继续用作提示。音频窗口内的长上下文和 DeepSeek 的前后文修订保留；Whisper 解码失败时启用默认温度回退重试，异常片段可能因此花费更久。
- 英文草稿中连续至少 4 次、总计至少 24 个词的相同循环会折叠为一次，并标记不确定，避免撑大字幕框；普通的少量重复保持原样。该处理用于显示及 AI 修订输入，原始识别仍完整保存在 `english-raw.txt` 和 `events.jsonl`，供核对真实说话内容。
- DeepSeek 一次校对当前片段和前两段，并参考更早最多六段。JSON 流完整返回并校验后一起更新英文和中文，避免显示未完成 JSON。过期版本的回复会被丢弃；排队的同段识别只保留最新版本。
- `events.jsonl` 的 `firstTokenLatency` 为兼容旧格式保留字段名，本版表示从当时音频末端到初版完整中文应用到字幕的耗时，不再是网络首 token 的时间。
- 2～3 秒仍是目标而非保证。较长音频用于后续修订，不要求等待 28 秒才显示字幕；停顿、网络和模型负载都会影响实际延迟。历史对比见 `research/2026-09-16-comparison.md`。
- 录音期间抑制系统自动闲置睡眠；合盖或主动休眠仍可能打断处理。收到休眠／音频设备变化通知时会结束录音并提示重新开始。
- 录音期间会持续写入内部原始音频，并每 5 秒强制同步到磁盘和更新恢复信息。异常退出后，下次打开应用或选择该默认目录时会自动生成 `audio.wav`；正常停止时原始恢复文件会在 WAV 成功生成后立即删除。恢复点之后接近 5 秒的数据可能尚未来得及落盘。
- 本版本通过两小时连续语音分段的加速模拟；真实麦克风连续两小时尚未验证。DeepSeek 已使用用户授权的课堂录音转录实测，不能将短样本当作长期稳定性保证。

## 重新构建和测试

需要 Xcode Command Line Tools（含 Swift、Clang）及 CMake。首次构建需要访问 GitHub 和 Hugging Face；脚本只向本项目目录写入依赖和模型。

```sh
./build.sh
./test.sh
./test.sh --whisper
```

`--whisper` 使用引擎自带的英语示例文件验证真实本地推理和静音输出，不读取麦克风、不调用 DeepSeek。运行环境需要允许访问 Metal GPU；受限沙箱可能阻止 GPU 内存分配。

重新编译会改变 ad-hoc 签名，系统可能再次询问麦克风或钥匙串权限。应用尚未进行 Developer ID 签名和苹果公证，定位是本机编译自用，不是对外分发的安装包。
